# Тестовые данные ProfileCompiler

Набор подготовлен под текущий формат программы с блоками `main` и `statics`.

## Формат `data.csv`

CSV не содержит заголовка. В каждой строке ровно четыре столбца:

1. `service - METHOD - endpoint`
2. `maximum`
3. `mean`
4. `count`

Текущая реализация использует только `mean`: значение преобразуется во `float` и округляется вверх через `math.ceil`.

## Сценарии

| Каталог | Назначение | Ожидаемый результат |
|---|---|---|
| `01_full_coverage` | Полностью успешный базовый сценарий | 100% покрытия для обоих сервисов |
| `02_partial_coverage` | Непокрытые endpoint и отсутствующий сервис | 85.71%, 75% и 0% по сервисам |
| `03_normalization_and_aggregation` | Пробелы, разные имена `{...}`, дубли scripts и CSV-строк | Успешная нормализация и 100% покрытия |
| `04_static_override_prompt` | Пересечение main/statics | Запрос продолжения; static перезаписывает расчёт |
| `05_script_conflict_prompt` | Один script в разных местах | Запрос продолжения; интенсивности складываются |
| `06_endpoint_template_conflict_prompt` | Шаблонный endpoint пересекается с конкретным | Запрос продолжения |
| `07_duplicate_statics_error` | Одинаковые static-ключи после `strip()` | Остановка на нормализации конфига |
| `08_case_sensitivity` | Разный регистр метода и сервиса | Частичное/нулевое покрытие из-за точного сравнения |
| `09_rounding_and_duplicate_rows` | Дробные mean и повторные CSV-строки | Проверка округления и агрегации |
| `10_invalid_config_structures` | Три ошибки структуры JSON | Остановка на валидации |
| `11_invalid_raw_profiles` | Заголовок, нехватка столбцов, нечисловой mean | Остановка на нормализации CSV |

## Содержимое успешного сценария

- `config.json` — входной конфиг;
- `data.csv` — сырой профиль;
- `scenario.json` — назначение и ожидаемый статус;
- `expected_profile.json` — ожидаемый итоговый профиль;
- `expected_coverage.json` — ожидаемый отчёт покрытия.

## Пример запуска

Из корня проекта:

```bash
python main.py \
  -c /путь/ProfileCompiler_test_data/02_partial_coverage/config.json \
  -p /путь/ProfileCompiler_test_data/02_partial_coverage/data.csv \
  -o results/test_profile.json
```

На Windows можно указать пути одной строкой:

```powershell
python main.py -c .\ProfileCompiler_test_data\01_full_coverage\config.json -p .\ProfileCompiler_test_data\01_full_coverage\data.csv -o .\results\test_profile.json
```

Для сценариев `04`–`06` нужно подтвердить соответствующий запрос продолжения. Для повторного запуска удалите выходной файл либо подтвердите его перезапись.

## Важные особенности, которые фиксирует набор

- `service` и HTTP-метод сравниваются с учётом регистра;
- содержимое фигурных скобок endpoint нормализуется до `{}`;
- пробелы у endpoint в CSV сейчас не удаляются, поэтому CSV-примеры намеренно не содержат лишних пробелов вокруг пути;
- сервисы, присутствующие только в конфиге, но отсутствующие в CSV, не появляются в отчёте покрытия;
- статичные значения не влияют на процент покрытия endpoint;
- при распределении одной интенсивности между несколькими scripts каждый результат округляется вверх.
